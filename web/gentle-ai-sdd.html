Comandos /sdd

10
Slash commands del flujo Spec-Driven Development. Cada uno corresponde a una fase del proceso.
/sdd-init SDD Core
Inicia el flujo Spec-Driven Development en cualquier proyecto. Detecta stack, tests, y activa Strict TDD Mode si hay tests disponibles. Convierte un repo desconocido en entorno SDD estructurado.
/sdd-init → "Stack: Flutter · Tests: sí · Strict TDD: ✅"
/sdd-onboard Onboarding
Guía al usuario a través del flujo SDD paso a paso. Explica cada fase, qué se espera, y cómo interactuar con el agente durante el proceso.
/sdd-onboard → "Bienvenido al SDD · Fase 1: Exploración · ¿Qué necesitas explorar?"
/sdd-explore Fase 1
Explora ideas SDD de forma amplia. Sin compromiso. Lee archivos, entiende el contexto, identifica patrones y oportunidades de mejora. Modelo recomendado: barato/rápido.
/sdd-explore → "Analizando codebase... 47 archivos · 3 patrones detectados · 2 áreas de mejora"
/sdd-propose Fase 2
Crea una propuesta de cambio SDD. Define objetivo, alcance, impacto y riesgos. Incluye análisis de costo-beneficio y alternativas. Modelo recomendado: medio.
/sdd-propose → "Propuesta: refactor RemoteConfig · Impacto: bajo · Beneficio: mantenibilidad ++"
/sdd-spec Fase 3
Escribe una especificación delta SDD basada en la propuesta aceptada. Define ACs (Criterios de Aceptación), comportamientos esperados, y límites del cambio. Modelo recomendado: potente.
/sdd-spec → "Spec: 12 ACs · 3 comportamientos · 0 breaking changes"
/sdd-design Fase 4
Crea el diseño técnico SDD. Arquitectura, interfaces, flujo de datos, archivos a tocar, y decisiones técnicas. Diagramas y justificaciones. Modelo recomendado: razonamiento.
/sdd-design → "Archivos: 4 · Patrón: Repository · Dependencias: 0 nuevas · Tests: 12"
/sdd-tasks Fase 5
Divide el cambio SDD en tareas atómicas. Cada tarea debe ser implementable y verificable de forma independiente. Incluye prioridad y dependencias entre tareas.
/sdd-tasks → "T1: Service layer · T2: UI widget · T3: Tests integración · Dep: T1→T2"
/sdd-apply Fase 6
Implementa las tareas SDD. Ejecuta el plan definido, archivo por archivo, siguiendo el diseño aprobado. Sin desviaciones sin re-planificar. Modelo recomendado: rápido/equilibrado.
/sdd-apply → "T1: ✅ · T2: ✅ · T3: ⏳ (depende de mock data)"
/sdd-verify Fase 7
Verifica la implementación contra la spec. Ejecuta tests, revisa que todos los ACs se cumplan, y produce un reporte de verificación. Modelo recomendado: crítico/potente.
/sdd-verify → "12/12 ACs ✅ · 47 tests GREEN · 0 regresiones"
/sdd-archive Archivo
Archiva un SDD completado. Guarda el contexto, decisiones, y resultados en Engram para referencia futura. Limpia el estado y cierra el ciclo.
/sdd-archive → "SDD #47 archivado · 4 memorias guardadas en Engram"

Comandos CLI (gentle-ai)

6
gentle-ai doctor Diagnóstico
Health check completo del ecosistema: bins, state.json, conectividad Engram, espacio en disco. Solo lectura.
gentle-ai doctor → "✅ 12/12 checks passed"
gentle-ai install Setup
Instala Gentle·AI en los agentes. --scope=workspace para aislar a un proyecto. Backups automáticos antes de cada instalación.
gentle-ai install --agent=opencode,claude --scope=workspace
gentle-ai sync Sincronizar
Sincroniza configuración, skills y perfiles SDD. Crea perfiles con modelos por fase.
gentle-ai sync --profile cheap:openrouter/qwen/qwen3-30b-a3b:free
gentle-ai update Actualizar
Actualiza Gentle·AI y componentes a última versión. Compara versiones de plugins con GitHub releases.
gentle-ai update → "✅ v1.24.0"
gentle-ai skill-registry refresh Skills
Escanea skills instaladas y convenciones del proyecto. Se ejecuta automáticamente en agentes con startup hooks.
gentle-ai skill-registry refresh → "Registry: 12 skills"
gentle-ai sync --profile-phase Perfiles
Asigna modelos específicos a fases concretas del SDD desde CLI.
gentle-ai sync --profile-phase cheap:sdd-design:anthropic/claude-sonnet-4-20250514

Engram — Memoria Persistente

6
engram projects list Listar
Lista todos los proyectos con su contador de recuerdos almacenados.
engram projects list → "CalcaApp: 47 · DockerHostinger: 23"
engram search <texto> Buscar
Busca decisiones, bugs y contexto de sesiones anteriores. Búsqueda semántica.
engram search "crash onboarding" → "ERB-55: onboarding lockout · ERB-53: gray-screen"
engram tui Visual
Navegador visual de memoria en terminal con interfaz TUI interactiva.
engram tui → [abre interfaz interactiva en terminal]
engram projects consolidate Mantener
Corrige deriva de nombres ("my-app" vs "My-App") y unifica proyectos duplicados.
engram projects consolidate → "🧹 3 proyectos fusionados"
engram sync Multi-máquina
Comparte memoria entre máquinas. Sincroniza contexto de trabajo entre dispositivos.
engram sync → "📤 47 memorias sincronizadas"
Engram MCP Tools API
Los agentes usan MCP tools para interactuar con Engram: mem_save (guarda contexto), mem_session_summary (resumen de sesión).
🔧 engram/mem_save → "Decisiones de la sesión guardadas"
